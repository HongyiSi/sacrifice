# 牺牲 · Sacrifice

**一款围绕“死亡的收益与代价”展开的双人卡牌策略游戏。**

每名玩家操控三个独立持牌的棋子，同时选择出牌，再按优先级结算。棋子阵亡后，亡语可能改变资源、复活角色，甚至直接改写胜负。因此，能够击杀对手，并不总意味着应该立刻击杀。

> 游戏策划 / 系统策划作品 · HongyiSi · **开发中**
> 当前重点是规则表达、平衡验证与移动端稳定性。本仓库提供源码和设计案例，演示视频展示预设局面；目前不作为稳定试玩版本发布。

## 核心规则

- **两个胜利方向**：击败敌方全部棋子，或集齐四枚胜利徽章；全灭需要等相关结算完成后判定。
- **三个独立单位**：各有生命、手牌与亡语。基础最大生命为 7，手牌上限为 8；生命上限可以被效果修改。
- **同时出牌**：正常情况下每个存活棋子每回合可出一张，也可不出。部分卡牌改变出牌额度。
- **分批揭示**：普通牌主优先级从高到低决定翻牌批次，次优先级从高到低决定批次内的结算顺序；反转效果可改变主优先级顺序。
- **死亡后的行动**：本回合阵亡且结算时仍处于死亡状态的棋子触发亡语；复活会取消尚未触发的亡语。部分牌有立即触发等明确例外。

截至 2026-10-21，数据表包含 **60 种普通牌、128 张初始牌库实例，以及 20 种亡语牌**。巨石、毒药等效果生成牌不计入这 60 种。开局发 4 张，再进行第一回合正常摸牌，通常首次出牌时有 5 张手牌。

## 我的工作与开发方式

我提出核心规则、卡牌效果和优先级方案，通过实际对局发现问题，再调整设计与交互。例如：为取义增加存活队友条件、统一手牌溢出规则、调整化牌为刃的类型与优先级，以及减少无效的自动触发。

项目使用 **AI 辅助编程与素材制作**。这里展示的是我对设计目标、规则取舍、测试场景和迭代方向的组织，以及相应的可运行实现；不将全部代码或美术表述为独立手工完成。技术案例明确区分设计意图、实现行为和测试结论。

开发环境为 **Godot 4.7.1 / GDScript**。克隆后用对应版本导入根目录 project.godot，等待资源导入后运行；本地 AI 对战无需连接游戏服务器。这是开发者运行入口，不是稳定发行包。

继续打磨的事项：移动 Safari 长时间对局稳定性、真人测试样本、平衡数据的覆盖范围，以及旧测试中随设计变更而失效的断言。AI 测试结果不能替代真人体验，也不代表已经完成商业级平衡验证。
